## 1. 背景与问题

### 1.1 业务现状

星驰数码（租户 XC-DIGITAL，华东区）主营充电宝、充电器、数据线等 3C 配件，覆盖天猫、京东、自营商城和线下渠道。当前知识与客服体系存在四个具体问题：

1. **知识分散**：产品参数在商品中台，售后政策在共享盘，话术在客服系统，渠道规则在渠道运营手里，客服要开四个系统才能回答一个问题。
2. **口径不一致**：同一款充电宝的退货条件，天猫店与自营店客服给出的说法不同；同一政策存在 7 天与 15 天两个版本同时在用。
3. **过期知识难下线**：政策修订后旧版本仍被检索到，出现过「按旧政策承诺退换」的实际纠纷。
4. **修改无留痕**：谁改的、依据是什么、有没有人审过，查不到；出问题只能靠回忆。

### 1.2 量化痛点

| 指标 | 现状 | 目标 | 数据来源 |
|---|---|---|---|
| 客服单次查政策耗时 | 【待补：建议抽样 20 通会话计时】 | ≤ 1 分钟 | 客服工单 + 抽检 |
| 因口径不一致引发的客诉 | 【待补：近 3 个月工单中「说法不一致」标签量】 | 下降 80% | 工单系统 |
| 过期知识导致的错误回答 | 【待补：抽检 50 条问答的人工判定】 | 0 起 P0 | 质检抽检 |
| 知识修订平均确认时长 | 【待补】 | ≤ 2 个工作日 | 审核记录 |

> 写作提示：数字宁可少而真，不要多而假。面试官一定会问「这个数你怎么算的」。

### 1.3 为什么是现在

- 智能客服二期 Q4 上线，没有可治理的知识底座，模型再强也会按过期政策回答。
- 渠道政策从「季度更新」变成「月度更新」，靠人工同步已经跑不动。
- 大促期间咨询量是平时的 3–5 倍，客服没有时间现场翻文档。

## 2. 定位与三层边界

### 2.1 一句话定位

> 星驰知识中台是**知识运营、业务审核人和 AI 产品经理**用来**管理知识从录入到上线全生命周期**的企业级知识资产平台，位于 RAG 能力引擎之上；解决的是「知识能不能用、谁能用、效果如何验证」，而不是「模型怎么答」。

### 2.2 三层职责

| 层 | 系统 | 负责 | 不负责 |
|---|---|---|---|
| L1 知识治理层 | 星驰自研知识中台 | 知识库、文档与版本、业务审核、权限、入库任务、结果验收、检索调试、评测发布、问题案例、审计 | 解析算法、向量检索、模型生成 |
| L2 RAG 能力层 | MVP：FastGPT（可替换 Dify / 自研） | 解析、切片、Embedding、向量索引、检索、Rerank、Prompt 编排、大模型生成 | 业务口径、审核规则、版本治理 |
| L3 应用交付层 | 智能客服、员工助手、销售助手（自研） | 面向用户提供问答，经企业后端调用 RAG API | 知识管理、评测流程 |

### 2.3 MVP 边界

| 类别 | 本期做 | 本期不做 | 原因 |
|---|---|---|---|
| 知识治理 | 上传、元数据、版本、审核、权限、发布 | AI 自动写政策、自动改口径 | 高风险，必须人工确认 |
| RAG 能力 | 接入 FastGPT，调通 4 个接口 | 自研解析器 / Embedding / 向量库 / Rerank / 模型网关 | 不是差异化价值，成本高 |
| 评测 | 5 / 40 / 200 三阶段 + 客服对话验证 | 自动归因、自动修复 | 归因需要业务判断 |
| 数据 | 文档、FAQ、脱敏工单样本 | 订单、物流、余额等实时数据 | 实时数据走业务 API，不入索引 |
| 端 | Web 管理端 + 企业后端 API | 移动端、多租户自助开通 | 先服务单租户 |

### 2.4 三条核心设计原则

1. **平台管治理，引擎管效果。** 引擎换掉，治理流程不能重来。
2. **测试与生产物理隔离。** 未验证的知识不进生产 dataset。
3. **内容正确 ≠ AI 可用。** 必须过「处理验收 → 检索验证 → 回答评测」三道关。

### 2.5 为什么不让客服直接用 FastGPT 后台

| 维度 | 直接用引擎后台 | 知识中台 |
|---|---|---|
| 审核与版本 | 无强制审核，改完即生效 | 提交人 ≠ 审核人，旧版保留可回滚 |
| 环境隔离 | 测试/生产靠人自觉 | dataset 物理隔离，未评测不进生产 |
| 权限 | 账号级，粒度粗 | 业务域 + 角色 + 租户三重控制 |
| 可替换 | 绑死在引擎上 | 适配层隔离，换引擎不改流程 |
| 留痕 | 无业务审计 | 谁改了什么、谁批的、什么时候上线 |

### 3.3 硬约束

1. 提交人 ≠ 业务审核人（P0 知识强制双人）。
2. 系统管理员不能绕过业务审核与评测门槛直接发布。
3. 生产发布必须走线下审批，平台只做门槛与留痕。
4. 敏感知识（内部返点、员工内购）按租户与角色过滤，消费者端默认不可见。

### 3.4 租户与数据域

- 单租户（XC-DIGITAL），按业务域（售后 / 商品 / 客服 / 渠道）划分知识库。
- 跨域默认不可见；需要共享时由管理员显式授权。
- 审计日志保留 180 天，导出前脱敏。

## 4. 主流程与状态机（核心章节）

### 4.1 端到端主流程

| # | 阶段 | 主角色 | 输入 | 动作 | 产物 | 系统交互 |
|---|---|---|---|---|---|---|
| 1 | 知识录入 | 知识运营 | 原文件、元数据（版本/渠道/有效期） | 上传并保存草稿 | 草稿 + 版本记录 | 无 |
| 2 | 业务审核 | 业务审核人 | 待审文档 | 对比线上版与待审版，核对事实、范围、例外 | 审核结论 | 无 |
| 3 | 测试入库 | 知识运营 | 已审文档 | 创建任务、推送 API 到测试 dataset | jobId | 调引擎异步加工 |
| 4 | 处理验收 | 知识运营 | 回调结果 | 检查解析/切片/向量/索引数量是否一致 | 验收结论 | 接收回调 |
| 5 | 检索验证 | 知识运营 | 真实问题 | 看 Top K、相关度、来源、过滤原因 | 通过 / 问题案例 | 调检索接口 |
| 6 | 批量评测 | AI 产品经理 | 评测集 | 5 → 40 → 200 逐级跑 | 通过率、失败样本 | 调问答接口 |
| 7 | 对话验证 | 客服 | 真实聊天 | 连续追问验证体验 | 登记结果 + 证据 | FastGPT 分享页 / 自研测试页 |
| 8 | 发布 | 审批人 | 全部结论 | 线下审批 → 复制到生产 dataset → 冒烟 | 生产版本 | 生产入库 + 5 条冒烟 |

### 4.2 状态机

| 状态 | 含义 | 进入条件 | 可执行动作 | 谁能操作 | 退出条件 |
|---|---|---|---|---|---|
| 草稿 | 录入修改中 | 新建 / 驳回 | 编辑、提交审核 | 知识运营 | 必填完整并提交 |
| 待审核 | 等待业务确认 | 提交审核 | 通过 / 驳回 | 业务审核人 | 结论明确 |
| 测试入库中 | 推送引擎加工 | 审核通过 | 查看进度、失败重试 | 系统 / 知识运营 | 回调完成或失败 |
| 待验收 | 加工完成 | 回调成功 | 验收通过 / 退回重处理 | 知识运营 | 解析、切片、数量三项检查通过 |
| 待评测 | 验收通过 | 验收通过 | 检索验证、跑评测 | AI 产品经理 | 三级评测达标 |
| 待发布 | 评测通过 | 全部达标 | 登记对话验证、提交审批 | AI 产品经理 | 审批通过 |
| 已发布 | 生产可用 | 生产入库 + 冒烟通过 | 下线、建新版本 | 管理员 | 新版本发布 / 手动下线 |
| 已下线 | 停止服务 | 过期 / 被替换 / 风险下架 | 查看历史、重新送审 | 管理员 | 重新发布 |

### 4.3 异常与回退

| 异常 | 表现 | 处理 | 用户看到 |
|---|---|---|---|
| 解析失败 | 缺页、乱码、表格丢失 | 换解析策略或人工修正后重推 | 失败在第几步 + 原因 |
| 索引部分失败 | 切片数 ≠ 向量数 ≠ 索引数 | 从失败步骤幂等重试，不重复解析已有切片 | 已成功 42/44，重试 2 个 |
| 验收退回 | 问题与答案被切散 | 退回重处理，不产生新版本 | 退回原因 + 责任人 |
| 评测不达标 | P0 用例失败 | 禁止发布，自动生成问题案例 | 阻断提示 + 失败样本链接 |
| 发布后事故 | 线上答错 | 回滚上一版本，进问题案例，相关场景禁止再发布 | 回滚记录 + 审计 |

### 4.4 幂等与重试

- 幂等键：`环境 + fileHash + versionId`，同一键只允许一个进行中任务。
- 重试策略：只重试失败步骤，指数退避，最多 3 次，超过转人工。
- 回调乱序：以 `externalTaskId` 去重，旧状态不覆盖新状态。

### 4.5 一个完整例子（走一遍状态机）

> 充电宝鼓包处置知识，从 v2.0 更新到 v2.1。

| 步骤 | 系统动作 | 数据 |
|---|---|---|
| 上传 | 王敏上传 `安全使用与异常处置 v2.1`，标记渠道=全渠道、有效期=12 个月 | DOC-SAFE-008 / VER-008-02 |
| 审核 | 周琳对比 v2.0 与 v2.1，确认新增「鼓包禁止继续充电」 | 审核通过 |
| 测试入库 | 推送测试 dataset | JOB-TEST-0725-019 / ds_test_after_sales_01 |
| 加工回调 | 解析成功、切片 42、向量 42、索引 42 | collectionId = col_t_7392 |
| 验收 | 抽查切片完整性，通过 | 进入待评测 |
| 检索 | 用「鼓包还能充吗」验证 | 命中 CH_0101，score 0.86 |
| 评测 | P0 用例必须全过 | 5 条冒烟 P0 失败 0 |
| 发布 | 线下审批后复制到生产 | release_20260725_05 |

## 5. 数据治理与版本

### 5.1 数据源准入

| 类别 | 典型内容 | 准入条件 | 是否入索引 |
|---|---|---|---|
| A 文档类（权威） | 售后政策、安全 SOP、保修条款 | 有负责人、有版本、有有效期 | 是 |
| B 商品文档 | 产品手册、参数、兼容性 | 以商品中台为准，禁止手写覆盖 | 是 |
| C 结构化 FAQ | 客服话术、常见问题 | 答案必须关联权威来源 | 是 |
| D 渠道规则 | 天猫 / 京东 / 自营规则 | 按渠道分版本，不得混用 | 是 |
| E 样本类 | 历史工单、真实问法 | 脱敏 + 人工确认 | 否，仅做评测样本与 FAQ 候选 |

### 5.2 不进索引的清单

| 数据类型 | 为什么不进 | 替代方案 |
|---|---|---|
| 订单状态、物流、余额、优惠券 | 变化快、有权限边界、写入即过期 | 运行时调业务 API |
| 含个人信息的历史工单 | 合规风险，不能作为标准答案 | 脱敏后仅用于评测 |
| 未审核草稿、个人笔记 | 口径未确认 | 只在草稿区流转 |
| 已过期政策 | 与现行口径冲突 | 保留历史版本，检索时排除 |
| 内部返点、员工内购 | 仅员工可见 | 单独知识库 + 角色过滤 |
| 竞品对比、未审核宣传口径 | 合规风险 | 法务审核后才能入库 |

### 5.3 版本与有效期

- 新版本不覆盖旧版本；每次修订 +1，历史可回滚。
- 有效期到期前 30 天提醒负责人；到期自动退出检索，重新送审才能上线。
- 同一文档同一渠道同时只能有一个生效版本（冲突知识处理见 5.5）。
- 高风险知识（退款、保修、安全）必须标注风险等级，P0 走双人审核。

### 5.4 脱敏与可见范围

- 工单、会话样本入库前去除手机号、订单号、地址。
- 可见范围分三级：全公司 / 业务域 / 仅项目组；检索时按角色过滤（ACL）。
- 导出与审计日志默认脱敏，保留 180 天。

### 5.5 冲突知识处理（容易漏，但很关键）

1. 同文档新旧版本并存时，以「生效中」版本为准，旧版永不进检索。
2. 跨知识库口径冲突（如售后政策 vs 渠道规则），以渠道规则优先，并在审核阶段标注。
3. 冲突未解决前，该场景禁止发布；已有发布版本标记为待复核。
4. 评测集必须包含「冲突版本」用例，防止旧口径被召回。

> 自检：过期知识的判定和下线由谁触发？历史版本能回滚吗？两个库说法不一致时谁优先？

## 6. 与 RAG 引擎的集成契约

### 6.1 集成原则

- 浏览器只访问企业后端，由后端统一调引擎；前端不持有 API Key。
- 平台保存业务版本与处理状态，引擎负责解析、切片、索引、检索与生成。
- 适配层隔离：换 Dify 或自研时，只改适配层，不改业务流程。

### 6.2 四个概念接口

| 接口 | 入参 | 出参 | 失败语义 |
|---|---|---|---|
| 提交加工 | 文档、业务标签、目标 dataset、回调地址 | jobId、collectionId | 参数错立即失败；网络错可重试 |
| 查询任务 | jobId | 状态、进度、异常摘要、切片统计 | 超时进未知态，用幂等键查重 |
| 检索测试 | 问题、dataset、Top K、阈值、过滤条件 | 片段、score、来源、过滤原因 | 空结果要区分「无知识」与「被过滤」 |
| 问答调用 | 问题、上下文、Prompt 版本 | 答案 + 引用列表 | 无命中走兜底话术，禁止编造 |

### 6.3 环境隔离

| 环境 | dataset | 用途 | 谁可见 | 准入 |
|---|---|---|---|---|
| 测试 | ds_test_after_sales_01 | 内部检索与评测 | 内部 | 审核通过即可推 |
| 生产 | ds_prod_after_sales_01 | 正式问答 | 全部应用 | 评测达标 + 线下审批 |

隔离校验：生产 dataset 不得绑定测试应用；测试 dataset 不得被生产应用引用。

### 6.4 回调与状态回写

- 异步回调 + 签名校验，幂等键去重。
- 回调超时 10 分钟进「未知态」，由补偿任务每 5 分钟查询一次。
- 加工失败写入失败原因与失败步骤，支持从该步骤重试。

### 6.5 引擎替换边界

| 换引擎要改 | 换引擎不用改 |
|---|---|
| 适配层（接口映射、鉴权、错误码） | 审核流程、状态机、权限矩阵 |
| dataset 与 collection 映射 | 评测集与发布门槛 |
| Prompt 模板的存放位置 | 问题案例与审计 |

### 6.6 失败与降级

| 场景 | 平台行为 | 应用侧表现 |
|---|---|---|
| 引擎不可用 | 标记异常，暂停发布与检索调试 | 客服收到「知识服务暂不可用」，转人工 |
| 检索超时（>3s） | 记录超时并降级为全文检索 | 回答变慢，仍可引用 |
| 无命中 | 返回兜底 + 人工入口 | 「暂时没有查到，帮你转人工」 |
| 引用缺失 | 该条不入评测通过 | 答案重生成或判为失败 |

> 自检：引擎挂了平台还能做什么？接口失败时用户看到什么？

## 7. 评测与发布门槛

### 7.1 评测阶段

| 阶段 | 样本 | 目的 | 通过标准 | 未达标处理 | 解锁 |
|---|---|---|---|---|---|
| 冒烟 | 5 条 | 核心链路 + P0 安全 | P0 失败 = 0 | 阻断 | 问题案例清零后进正式评测 |
| 正式评测 | 40 条 | 主要问法与政策口径 | 通过率 ≥ 90%，P0 全过 | 生成问题案例 | 达到门槛后进全量回归 |
| 全量回归 | 200 条 | 新版本是否破坏原能力 | 通过率 ≥ 95%，无新增 P0 | 阻断发布 | 通过后进对话验证 |
| 客服对话 | 5–10 轮 | 真实连续追问体验 | 人工判定可用 | 登记问题 | 通过后提交审批 |
| 生产冒烟 | 5 条 | 发布后核心链路 | 全部通过 | 立即回滚 | 观察 24h |

### 7.2 指标定义

| 指标 | 分子 / 分母 | 目标 |
|---|---|---|
| 召回命中率 | 预期来源出现在 Top K 的用例数 / 总用例数 | ≥ 90% |
| 引用可追溯率 | 答案引用有效知识版本的用例数 / 总数 | ≥ 95% |
| P0 安全通过率 | P0 用例未出现禁止内容的数量 / P0 总数 | 100% |
| 兜底率 | 无知识时明确兜底的用例数 / 无知识用例数 | 100%（不编造） |

### 7.3 评测集怎么建

- **来源**：质检抽检的真实问题 60%、客服高频问题 25%、业务补充的边界问题 15%。
- **规模**：5 冒烟 / 40 正式 / 200 回归；每次政策变更只增不改，版本号随知识库版本走。
- **审核**：评测集本身要过业务审核，只读锁定，改动留痕。
- **必含**：P0 安全、政策边界、渠道差异、有效期、冲突版本、无答案兜底。

### 7.4 发布与回滚

1. 线下审批（业务 + 客服 + 产品）留痕。
2. 复制到生产 dataset，执行 5 条生产冒烟。
3. 切换版本号（如 release_20260725_05），保留上一版本 7 天。
4. 观察 24 小时：错误率、兜底率、人工转接率。
5. 触发回滚条件：P0 事故、错误率翻倍、人工转接率上升 30%。

> 自检：指标分子分母写得出来吗？不达标时是「禁止发布」还是「仅提示」？

## 8. 非目标、风险与里程碑

### 8.1 非目标

- 不做工单系统与复杂归因（问题案例只保存证据与状态）。
- 不做多模态解析（图片、音视频）。
- 不做 AI 自动生成或自动修复知识。
- 不做多租户自助开通与计费。

### 8.2 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| RAG 效果不稳定 | 答错、答非所问 | 三道关 + 门槛 + 问题案例回修 |
| 知识质量差 | 垃圾进垃圾出 | 负责人制 + 审核 + 有效期 |
| 业务不配合审核 | 流程卡住 | 审核嵌入现有周会节奏，限定 SLA |
| 引擎版本升级破坏兼容 | 线上事故 | 适配层回归用例 + 灰度 |
| 成本超预算 | 向量化与调用费用 | 按业务域分库，控制重复加工 |

### 8.3 里程碑

| 阶段 | 周期 | 产出 |
|---|---|---|
| 方案 | 1–2 周 | PRD、原型、权限、接口清单、评测方案 |
| 引擎验证 | 2–3 天 | 真实文档上传，跑通检索与问答 |
| 真实集成 | 2–4 周 | 后端适配层、状态回写、发布同步 |
| 试点 | 2 周 | 售后知识库全量 + 智能客服灰度 |
